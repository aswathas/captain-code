Chapter 01 — The Situation

181 skills on the machine.
No way to see which ones were on.

The CLI is excellent at doing the work and terrible at telling you the state of the install. You know the skills are there. You do not know which are enabled, which are parked, which plugins are switched on, what the MCP servers point at, or what last month cost.

So the state lives on disk, unread, until a tool writes a new line into it. The Captain Command Centre reads the same files the tool reads, in the same machine — no wrapper, no exported report, no second source of truth.

  • Real files, real paths — every number traces back to a file on your disk
  • Nothing is deleted to disable it — folders move aside, nothing is destroyed
  • Secrets never leave the process — they render as 125 chars · hidden
  • Every mutation is reversible — a timestamped backup sits beside each file

Chapter 03 — The Mission

Five steps to a command centre
over your own install.

  1. 01

    Deploy

    Clone, install, build, serve. One command if you let the installer do it.

    git clone https://github.com/aswathas/claude-command-center.git
cd claude-command-center
npm install
npm run build
npm start

    Windows: start.cmd does it in one click. macOS/Linux: ./scripts/install.sh.

  2. 02

    Plug in your Claude Code

    By default the console reads ~/.claude and ~/.claude.json — the install you already have, auto-detected. Point it somewhere else with two environment variables: a scratch profile, a second machine, a test rig. 

    CLAUDE_HOME=/path/to/.claude \
CLAUDE_JSON=/path/to/.claude.json \
npm start

    Run npm run doctor first — it prints the exact paths it detected, and whether they hold skills, plugins, MCP servers and transcripts.

  3. 03

    Open the console

    http://127.0.0.1:8787. Loopback only. Nothing on the network can reach it until you say otherwise. For live development, npm run dev runs the API on 8787 and Vite on 5173 with hot reload.

  4. 04

    Take the wheel

    Toggle a skill, park a plugin, add an MCP server, edit a setting, rewrite a memory file. Every change writes the real file and drops a .bak.<timestamp> beside it. Secrets read back masked, and merged back in place on save — a round-trip can never replace a live token with a placeholder.

  5. 05

    Take it to the phone

    Settings → Phone access puts the console on your LAN address, with a QR code in the panel and an access code every request must carry. The phone answers the only question that matters at 1am: is it still going? Switch phone access off and the console closes to the outside world immediately.

Chapter 04 — The Oath

Safety rules the code
enforces, not the docs promise.

Loopback by default. The server binds to 127.0.0.1. Nothing listens on the network until phone access is explicitly switched on.
Credentials are never read. ~/.claude/credentials.json is refused, not skipped.
Masked on the way out. Any key matching token / secret / key / auth / cookie, and anything shaped like a provider key, renders as 125 chars · hidden.
Masked values merge back on the way in. Saving the raw settings editor restores the stored secrets instead of writing placeholders over them.
Every write is backed up. settings.json.bak.<timestamp> sits beside the file it replaced.
Writes stay inside the walls. Confined to the Claude home, the app cache, and ~/.claude.json.
Disabling is not deleting. Skills and MCP servers are moved aside — the folder is still there tomorrow.
No destructive default. Deleting means deleting. It is never the default action on a control.

Chapter 05 — The Ledger

Token telemetry that cannot
drift from the tool's own numbers.

Claude Code writes one JSONL transcript per session. Every assistant message carries a usage block, and each session ends with a cost-state record holding Claude Code's own accounting.

The detail that took the longest: the same API message can be written more than once inside a transcript, so naive summing inflates your token count. The indexer dedups on (sessionId, message.id), and takes cost from the session's own cost-state record when it has one — so the dashboard cannot disagree with the tool about the same history.

  • 9.2scold scan of 1,292 transcripts / 869 MB
  • 0.13srescan, served from the per-file cache
  • (mtime, size)cache key — only changed files are re-read
  • 0synthetic day buckets — a session's cost lands on a real day
